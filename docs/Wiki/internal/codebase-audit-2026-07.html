Codebase Audit — July 2026

Static audit of the IntelliJ plugin, Blender-side Python runtime, templates, resources, and tests.

Scope: hand-written files under src/main and src/test, Gradle/plugin metadata, and MessageBundle.properties. Generated build output and the embedded 33,324-line get-pip.py payload were excluded from line-by-line review.

1) Executive Summary

SeverityCountPrimary themes
High4Unauthenticated local command execution, unusable discovered paths, invalid generated Python, runtime dependency integrity/reliability.
Medium11Session spoofing, template escaping, platform discovery, run/debug lifecycle, global-state races, excess reloads.
Low4Dead APIs/state, redundant abstractions, localization drift, stale test expectation.
Most urgent: authenticate the Blender HTTP command channel, correct scanner output paths, and fix the two Python templates before shipping. The default project wizard currently creates a syntactically invalid src/__init__.py.

Confidence convention: “Confirmed” means the behavior follows directly from source or a validation result. “Inferred” means the source strongly suggests the failure but the audit did not execute Blender or attach a live debugger.

2) Recommended Remediation Order

  1. Introduce a per-launch secret on both local HTTP servers; reject unknown sessions and unauthenticated commands.
  2. Fix and syntax-test generated Python templates; serialize manifest/Python values with format-aware escaping and correct tuple types.
  3. Make every detected installation store the actual launch target: executable on Windows/Linux and app bundle on macOS.
  4. Replace runtime-time package installation with a version-verified, timeout-bounded strategy; at minimum enforce installed versions.
  5. Add scanner, HTTP protocol, template-content, and run/debug lifecycle tests before addressing the maintenance findings.

3) Security and Trust-Boundary Findings

AUD-001 — Blender command server permits unauthenticated local code execution

Severity: High · Confidence: Confirmed · Category: Vulnerability

The Blender runtime binds a Flask server to loopback, accepts any JSON POST, and dispatches solely on the caller-provided type. The script command accepts an arbitrary filesystem path and executes it with runpy.run_path. The random high port is not authentication; another local process can scan the range or observe process state.

Impact: any process running as the same user can execute Python in Blender, reload add-ons, or terminate Blender while a session is active.

Recommendation: generate a cryptographically random launch secret, transmit it through the child environment, require it in a header on every request, compare it in constant time, validate payload schemas, and consider a Unix-domain socket where supported.

Evidence: /blender_pycharm/src/main/blender-runtime/include/blender_pycharm/communication.py:45, :115; /blender_pycharm/src/main/blender-runtime/include/blender_pycharm/operators/script_runner.py:23, :28.

AUD-002 — Editor callback server accepts fabricated sessions

Severity: Medium · Confidence: Confirmed · Category: Vulnerability

The IDE server also binds to loopback without authentication. An unknown identifier only produces a warning; the payload is still inserted into both setup and active-session maps. A local process can therefore register an attacker-selected command port as the latest Blender session. The request body is also read without a size limit.

Impact: session spoofing, command redirection to a local listener, log/heap pressure from oversized bodies, and confusing debugger attachment behavior.

Recommendation: reject identifiers not present in pendingSessionIdentifiers, require the per-launch secret, cap body size before parsing, accept only the expected path/content type, and return an error for unknown payload types.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/core/BlenderEditorServerService.kt:160, :171, :178, :200, :207.

AUD-003 — Runtime dependencies are installed without integrity or installed-version enforcement

Severity: High · Confidence: Confirmed · Category: Vulnerability / Reliability

Every debug bootstrap asks for debugpy, requests<=2.29.0, werkzeug<=3.0.3, and flask<=3.0.3. Availability is checked only by importing the package name; an already-installed version outside the requested range is accepted. Missing packages are downloaded from the configured/default package index without hashes and installed into persistent Blender user modules.

Impact: the compatibility caps do not work after the first install or external upgrades, and bootstrap expands the supply-chain attack surface of launching Blender.

Recommendation: inspect distribution metadata with importlib.metadata and packaging.specifiers, pin tested versions, prefer a plugin-managed isolated directory, and use a lockfile/wheel hashes if automatic installation remains.

Evidence: /blender_pycharm/src/main/blender-runtime/include/blender_pycharm/__init__.py:49; /blender_pycharm/src/main/blender-runtime/include/blender_pycharm/installation.py:19, :40, :45, :108.

AUD-004 — Template values are inserted without format-aware escaping

Severity: Medium · Confidence: Confirmed · Category: Data integrity

Wizard values such as name, description, author, website, tags, permission reasons, and license are interpolated directly into TOML and Python string literals. Quotes, backslashes, or newlines can create invalid output or inject additional generated statements/keys. This is primarily a project-integrity issue because the user supplies the values, but generated files should still preserve input safely.

Recommendation: centralize TOML string/array serialization and Python literal serialization, then test quotes, backslashes, newlines, Unicode, and Velocity metacharacters.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/wizard/BlenderNewProjectGenerator.kt:202, :221, :263; /blender_pycharm/src/main/resources/fileTemplates/internal/BlenderManifest.ft:4; /blender_pycharm/src/main/resources/fileTemplates/internal/NewProjectMainScript.ft:19.

4) Potential Bugs and Correctness Findings

AUD-005 — Default generated add-on script has invalid indentation

Severity: High · Confidence: Confirmed · Category: Bug

The default wizard enables example code, but the template emits the bodies of register, unregister, and the if __name__ block at column zero. The public “Main Script” file template has the same if-body defect.

def register():
for cls in classes:
        bpy.utils.register_class(cls)

if __name__ == "__main__":
register()

Recommendation: repair indentation and add a generator test that parses the rendered file with a Python parser rather than checking only that the file exists.

Evidence: /blender_pycharm/src/main/resources/fileTemplates/internal/NewProjectMainScript.ft:46, :64; /blender_pycharm/src/main/resources/fileTemplates/Main Script.py.ft:10; /blender_pycharm/src/test/kotlin/com/sakurasedaia/blenderdevelopment/wizard/BlenderProjectGeneratorTest.kt:35.

AUD-006 — Generated bl_info versions use the wrong Python types

Severity: Medium · Confidence: Confirmed · Category: Bug

The template writes extension and Blender versions as strings. Blender add-on metadata expects integer tuples such as (1, 0, 0) and (4, 2, 0). Correcting indentation alone will still leave malformed metadata.

Recommendation: validate semantic versions in the wizard and render tuple literals explicitly.

Evidence: /blender_pycharm/src/main/resources/fileTemplates/internal/NewProjectMainScript.ft:21; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/wizard/BlenderNewProjectGenerator.kt:265.

AUD-007 — Detected Windows and custom installations store non-launchable directories

Severity: High · Confidence: Confirmed · Category: Bug

The Windows scanner probes blender.exe but stores its parent version directory. Custom non-macOS candidates similarly store the candidate directory after finding a binary inside it. The tool window copies that value into ProjectConfig.blenderPath, and the launcher passes it directly as the command.

Impact: selecting a successfully detected Windows/custom installation can fail at launch with a directory-as-executable error.

Recommendation: define the persisted field as a launch target and store blender.exe/blender on Windows/Linux; retain the .app bundle only for the macOS path handled by ExternalProcessBuilder.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/core/BlenderInstallationScanner.kt:148, :325; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/ui/toolwindow/BlenderToolWindowContent.kt:284; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/core/BlenderLauncher.kt:69.

AUD-008 — Linux discovery searches for blender-runtime instead of Blender

Severity: Medium · Confidence: Confirmed · Category: Bug

The Linux fast path runs which blender-runtime, and the Homebrew paths use blender-runtime throughout, while the normal Blender executable is blender. Explicit /usr fallbacks partly mask this, but PATH-only and Homebrew installs can be missed.

Recommendation: use blender consistently and test PATH, package-manager, Homebrew, and custom-root layouts.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/core/BlenderInstallationScanner.kt:233, :240, :341.

AUD-009 — OS compatibility lookup uses incompatible key vocabularies

Severity: Medium · Confidence: Confirmed · Category: Latent bug

The version table is keyed by win, mac, and linux; SystemHelper looks up windows, macos, and linux. All Windows and macOS compatibility checks therefore return false. The current test derives its expectation with the same mismatched key, so it passes by accepting that no compatible version exists.

Recommendation: introduce a single OS enum/key mapping and use explicit Windows/macOS assertions in tests.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/lib/BlenderVersions.kt:63, :71; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/util/SystemHelper.kt:72; /blender_pycharm/src/test/kotlin/com/sakurasedaia/blenderdevelopment/util/SystemHelperTest.kt:39.

AUD-010 — Normal Run does not establish or link the development runtime

Severity: Medium · Confidence: Inferred · Category: Bug

Debug mode extracts the runtime, creates links, loads the add-on, and establishes the HTTP session. Normal Run instead renders BlenderRuntimeRepoSyncLaunch, which only refreshes and attempts to enable already discoverable module names. It neither creates a link nor starts the command server. A newly generated project that has never been linked by Debug is therefore unlikely to load on its first Run.

Recommendation: share one bootstrap path for Run and Debug, with debugger startup as an option, and cover first-run behavior in a Blender integration test.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/core/BlenderLauncher.kt:128, :145, :197, :233; /blender_pycharm/src/main/resources/fileTemplates/internal/BlenderRuntimeRepoSyncLaunch.py.ft:1.

AUD-011 — “Just my code” mutates application-wide debugger settings per session

Severity: Medium · Confidence: Confirmed · Category: Concurrency bug

A project-scoped attach service changes global PyDebuggerSettings and restores captured values when its process terminates. Overlapping debug sessions can capture and restore each other’s temporary state, leaving global settings incorrect for unrelated projects.

Recommendation: configure filters on the debug process/session when the API permits. If global mutation is unavoidable, serialize ownership and restore only when the final owner releases it.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/core/BlenderDebugAttachService.kt:221.

AUD-012 — Reload-on-save reacts to every saved IDE document

Severity: Medium · Confidence: Confirmed · Category: Bug / Performance

The global file-document listener does not resolve the document’s file, check project ownership, restrict Python/add-on files, or debounce saves. Saving unrelated files—or Save All—can send repeated full reload commands.

Recommendation: resolve with FileDocumentManager.getFile, require a file under configured source/script roots, and coalesce rapid saves.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/run/BlenderDebugProgramRunner.kt:52, :59.

AUD-013 — Editor context action can execute a different file than the one clicked

Severity: Medium · Confidence: Confirmed · Category: Bug

Action enablement uses CommonDataKeys.VIRTUAL_FILE from the invocation context, but execution discards that event file and queries FileEditorManager.selectedFiles.firstOrNull(). Context-menu use can therefore execute the active editor file rather than the clicked file.

Recommendation: pass the action event’s file into the command service and validate it at the boundary.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/ui/actions/BlenderRuntimeActions.kt:57, :62; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/core/BlenderRuntimeCommandService.kt:71, :162.

AUD-014 — Process and HTTP payload capture is unbounded

Severity: Medium · Confidence: Confirmed · Category: Resource exhaustion

ExternalProcessBuilder reads the entire combined process output into one string. Version probes normally produce little output, but the public helper has no bound. The IDE callback server similarly reads the complete request body before parsing.

Recommendation: cap captured bytes, retain a diagnostic tail, abort oversized HTTP requests with 413, and document truncation.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/process/ExternalProcessBuilder.kt:64; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/core/BlenderEditorServerService.kt:178.

AUD-015 — Runtime package installation can block bootstrap indefinitely

Severity: Medium · Confidence: Confirmed · Category: Reliability

All pip/ensurepip subprocess calls omit a timeout. DNS, proxy, index, or child-process hangs can prevent Blender startup from completing with no recovery path.

Recommendation: set a bounded timeout, terminate the child process on expiry, and report a recoverable dependency failure.

Evidence: /blender_pycharm/src/main/blender-runtime/include/blender_pycharm/installation.py:49, :70, :85.

5) Unused Code and Unnecessary Abstraction

AUD-016 — Multiple production APIs have no production callers

Severity: Low · Confidence: Confirmed · Category: Unused code

Unused surfaceObservation

AUD-017 — Persisted settings advertise behavior that does not exist

Severity: Low · Confidence: Confirmed · Category: Unused state

Code-completion path, download path, cleanup-after-install, and download-cache size are persisted. Some appear in Settings, but no production workflow consumes them; cache size is not even exposed by the UI. These controls imply capabilities the plugin does not implement.

Recommendation: hide/remove dormant controls and preserve migration compatibility only if the feature is scheduled, or implement the owning download/stub workflow.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/state/PluginConfig.kt:36, :38, :41; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/ui/settings/BlenderSettingsContent.kt:69.

AUD-018 — Version registry and startup loading contain redundant layers

Severity: Low · Confidence: Confirmed · Category: Unnecessary abstraction

An immutable in-memory list is wrapped by a volatile lazy cache, a private “safe” getter, a public getter, and a LIST alias. Separately, loadPluginState and loadWorkspaceState simply return fields and are invoked as if they force persistence loading. These layers obscure ownership without adding behavior.

Recommendation: expose one immutable registry property and remove the no-op loading methods after verifying service initialization behavior against the targeted IntelliJ build.

Evidence: /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/lib/BlenderVersions.kt:87; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/state/PluginConfig.kt:156; /blender_pycharm/src/main/kotlin/com/sakurasedaia/blenderdevelopment/state/ProjectConfig.kt:230.

AUD-019 — One visible title bypasses the bundle and tests have drifted from localized text

Severity: Low · Confidence: Confirmed · Category: Localization / Test drift
