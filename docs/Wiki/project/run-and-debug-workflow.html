Run and Debug Workflow

Execution pipeline from run configuration to external Blender process

Scope: validation, command construction, runtime script generation, editor handshake, debugger attach, and process lifecycle handling.

1) Debugger Compatibility

Python debug attach in this plugin targets debugpy over DAP and requires PyCharm 2026.1+.

Older IDE baselines do not provide the required attach behavior for this workflow.

2) End-To-End Pipeline

  1. BlenderLaunchRunConfiguration.checkConfiguration() validates Blender path.
  2. getState() builds CommandLineState.
  3. Launcher.startBlender() resolves path and builds launch command.
  4. For debug/runtime mode, launcher renders BlenderRuntimeLaunch.py.ft into scratch.
  5. BlenderEditorServerService opens a random localhost editor port and creates a unique launch identifier.
  6. ExternalProcessBuilder.startProcessHandler() creates an OSProcessHandler with launch environment variables.
  7. BlenderDebugAttachService waits for runtime setup payload and auto-attaches the Python debugger in Debug runs.
  8. BlenderDebugProgramRunner subscribes to file-save events during Debug run lifetime and triggers runtime reload when ProjectConfig.reloadOnSave is enabled.
  9. On process termination, generated bootstrap script is deleted and session tracking is released.

3) Launch Argument Assembly

Arguments are assembled from three sources:

SourceDetails
Log levelMapped from ProjectConfig.BlenderLogLevel into --log-level <value>.
Workspace run argsParsed from ProjectConfig.getRunArguments() via ParametersListUtil.parse.
Script injectionAlways injects --python <scratch script>: Debug uses runtime bootstrap; normal Run uses a lightweight repo/add-on refresh script.
Environment mergeMerges PluginConfig.globalEnvironmentVariables first, then project environmentVariables (project overrides duplicate keys).
Runtime directory envPublishes project scriptDirectories as BLENDER_PYCHARM_SCRIPT_DIRECTORIES for runtime addon loading/reload.
Handshake envSets EDITOR_PORT and BLENDER_PYCHARM_IDENTIFIER; also forwards runtime env settings such as BLENDER_PYCHARM_LOG_LEVEL. During migration it still publishes legacy VSCODE_* keys for backward compatibility.
Debug attach optionsUses handshake debugpyPort and path mappings and attaches via Python DAP (debugpy).

4) Generated Bootstrap Script

The runtime script inserts extracted runtime include into sys.path, builds the editor callback URL from EDITOR_PORT, and calls blender_pycharm.startup(...). It inspects the imported startup signature and only passes supported keyword arguments for compatibility with older runtime copies.

include_dir = Path('${includeDirLiteral}')
if include_dir.exists():
    sys.path.insert(0, str(include_dir))

import blender_pycharm
import inspect
editor_port = os.environ.get("EDITOR_PORT", "").strip()
editor_address = f"http://127.0.0.1:{editor_port}/" if editor_port else None
addons_to_load = []  # sourceFolder addon root + scriptDirectories addon roots or discovered child add-ons
startup_kwargs = {
    "editor_address": editor_address,
    "addons_to_load": addons_to_load,
    "wait_for_debugger": False,
    "project_root": '${projectPathLiteral}',
    "source_folder": '${sourceFolderLiteral}',
    "addon_symlink_name": '${addonSymlinkNameLiteral}',
}
signature = inspect.signature(blender_pycharm.startup)
filtered_kwargs = {
    key: value
    for key, value in startup_kwargs.items()
    if key in signature.parameters
}
blender_pycharm.startup(**filtered_kwargs)

5) Process Handling and Cleanup

  • ProcessTerminatedListener.attach(processHandler) integrates with IDE run UI.
  • Custom listener removes generated bootstrap scripts when process exits.
  • ExternalProcessBuilder handles macOS bundle binary resolution and command adaptation.
  • BlenderEditorServerService accepts setup payloads from Blender and tracks them by session identifier.
  • Session tracking removes stale pending and inactive session entries after bounded TTL windows.
  • BlenderDebugAttachService starts a Python DAP attach configuration to 127.0.0.1:<debugpyPort>.
  • Debug runner save-listener subscription is disconnected when the process terminates.
  • On startup, stale scripts are cleaned from scratch directory.
  • Runtime HTTP command calls use bounded connection/request timeouts and evict unreachable sessions from the active cache.
  • Normal Run mode executes a small bootstrap that refreshes add-on/extension repos and reloads the configured add-on candidate before interactive use.

6) Runtime Commands From IDE

The plugin exposes runtime command actions through the tool window, Tools menu, and Python editor context menu.

CommandIDE behaviorRuntime handler
Run ScriptSends selected Python file path to active Blender session.operators/script_runner.py (type="script")
Reload Add-onSends configured add-on module names and directories.operators/addon_update.py (type="reload")
Stop BlenderSends stop command to the active session.operators/stop_blender.py (type="stop")

Blender's Python communication layer logs when each command is received, queued on the main thread, executed, and completed. Handler exceptions are logged with tracebacks; reload logging also records resolved targets, unavailable directories, module disable/enable failures, and successful module reloads. Unknown command types are logged and rejected with HTTP 400.

7) Complex API Snippets

Run profile state implementation

override fun getState(executor: Executor, environment: ExecutionEnvironment): RunProfileState {
  val shouldAttachDebugger = executor.id == DefaultDebugExecutor.EXECUTOR_ID
  return object : CommandLineState(environment) {
    override fun startProcess(): OSProcessHandler {
      return Launcher.getInstance(project).startBlender(
        BlenderArguments(
          blenderPath = ProjectConfig.getInstance(project).getBlenderPath().trim(),
          debugger = shouldAttachDebugger,
        )
      )
    }
  }
}

Scratch script generation

PluginResources.createFromTemplate(
  project = project,
  name = scriptFileName,
  template = "BlenderRuntimeLaunch",
  destination = scratchVfsDirectory,
  internal = true,
  "includeDirLiteral" to toPythonStringLiteral(includeDirectoryPath.toString()),
  "projectPathLiteral" to toPythonStringLiteral(projectBasePath),
  "sourceFolderLiteral" to toPythonStringLiteral(sourceFolder),
  "addonSymlinkNameLiteral" to toPythonStringLiteral(addonSymlinkName),
)
