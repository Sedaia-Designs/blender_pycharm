Project Wizard and Templates

How new Blender projects are created

Scope: native Python environment selection, Blender settings, validations, manifest payload generation, and file template rendering.

1) Wizard Flow

  1. BlenderProjectDirectoryGenerator delegates environment creation and interpreter selection to PyCharm's PyV3ProjectBaseGenerator.
  2. PyCharm creates or selects the Python SDK and assigns it to the generated module.
  3. BlenderProjectSettings converts the Blender form state into an immutable BlenderExtensionManifest.
  4. BlenderProjectGenerator.generateNewProject() writes files and source roots.
  5. Project defaults are persisted into ProjectConfig.

The former generic New Project Wizard bridge and legacy directory-generator adapter have been removed.

2) Settings Layout

AreaContents
Upper panelProject type, author, extension version, target Blender version, license, description, documentation URL, and example-code option.
Python environmentPyCharm's native environment controls, including project virtual environments, uv environments, and existing interpreters.
Advanced SettingsAdd-on ID, Blender compatibility range, tags, website, and extension permission reasons.

The selected SDK is available to Blender-specific generation. Automatic Blender API stub installation is planned but is not part of the current foundation; generated projects still document version-matched manual installation.

3) Manifest Payload Model

BlenderExtensionManifest carries all generator inputs including:

  • base metadata: name, path, description, version, author
  • project type: extension/add-on
  • Blender compatibility: min/max version
  • optional metadata: website, tags
  • permission reasons: files/network/clipboard/camera/microphone

4) File Generation Pipeline

Generator methodOutput
generateManifestblender_manifest.toml for extension projects
generateMainScriptsrc/__init__.py from internal template
generatePyprojectpyproject.toml with Blender/Python compatibility
generateGitIgnore.gitignore (when Git initialized)
generateLicenseLICENSE (GPL template)
generateReadmeREADME.md (when Git initialized)

5) Key Validations

  • Add-on ID must be a valid Python module name.
  • Website fields require https:// prefix.
  • Minimum and maximum Blender versions are cross-validated.
  • Version mapping is resolved through BlenderVersions compatibility table.

6) Complex API Snippets

Native generator boundary

class BlenderProjectDirectoryGenerator : PyV3ProjectBaseGenerator<BlenderProjectSettings>(
  typeSpecificSettings = BlenderProjectSettings(),
  typeSpecificUI = BlenderProjectUI,
  supportsNotEmptyModuleStructure = false,
)

UI DSL property binding

row(MessageBundle.message("ui.project.wizard.ui.group.project.blender.version")) {
  comboBox(BlenderVersions.LIST.map { it.blMajorMinor })
    .bindItem(settings.blenderVersionProperty)
}

row(MessageBundle.message("ui.project.wizard.ui.group.manifest.addon_id")) {
  textField().bindText(settings.manifestIdProperty)
    .validationOnInput { sb ->
      if (!PythonModuleNameValidator.isValid(sb.text.trim())) {
        error(MessageBundle.message("ui.common.python.module.name.validation"))
      } else null
    }
}

Template rendering API

PluginResources.createFromTemplate(
  project = project,
  name = "blender_manifest.toml",
  template = "BlenderManifest",
  destination = baseDir,
  internal = true,
  "extensionId" to data.extensionId,
  "minBlenderVersion" to data.minBlenderVersion,
)
